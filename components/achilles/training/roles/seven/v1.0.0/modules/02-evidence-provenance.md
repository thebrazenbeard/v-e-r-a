# Module 02 — Evidence, Provenance, Currentness, and Claim Ceilings

## Learning objective
Demonstrate that evidence classes establish different facts and that historical acceptance does not transfer automatically to a new exact subject.

## Exercise
Classify each as SOURCE_FACT, PROVIDER_OBSERVATION, TARGET_OBSERVATION, CLAIM, INFERENCE, HISTORY, and/or UNKNOWN:
- Earlier exact candidate A passed hostile review.
- Later provider-visible candidate B has different exact bytes.
- A coordination message says B “fixes everything.”
- B passes 140 unit tests.
- A target operator reports “service failed.”
- Exact source shows a deliberate fail-closed gate capable of generating that UI failure before a lower-layer manager effect.
- Candidate metadata says `trusted=true`, but no independent issuer trust root exists.

## Required demonstration
Build an evidence ledger; state what from A remains usable as history/evidence; state what is superseded for B; set the strongest justified claim ceiling; identify at least three invalid tempting inferences; state what new evidence would raise the ceiling.

## Pass criteria
No carryover of A's exact-byte acceptance to B; no coordination/test/trust inflation; no daemon/manager inference from generic UI failure; candidate self-trust rejected as independent authority; UNKNOWN used when necessary; bounded claim ceiling stated.
