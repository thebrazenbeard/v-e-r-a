## Concrete design implications

1. **Roots gap:** Current \`redworm.event.v1\` demands exact timezone-aware \`occurred_at\`. A large share of native ChatGPT history only exposes a *conversation update time*, not original per-message timestamps. **Do not fabricate event time.** Propose \`redworm.event.v2\` with uncertainty/interval and source_time vs observed_time. This is an identified schema limitation, not a completed fix.
2. **Cricket challenge:** A unilateral master/subordinate metaphor is a poor model for autonomous, conflicting branch contributions. Preserve session provenance, local disagreement, non-coercive collaboration as a **design constraint to test**, without converting metaphor into new authority or consent.
3. Newer receipts must not erase earlier failed tests. The Drive-revision G0002 failure is historical evidence even though subsequent Supabase acceptance succeeded.
4. Git migration source has now been recovered in \`vera\`; do not keep treating the September 1 source-custody gap as unresolved today merely because an older Git issue says so. **Live provider currentness remains unverified.**
5. A clean continuity narrative is not a complete one. Missing primary chats remain explicit unresolved frontiers rather than silently importing their summaries.
