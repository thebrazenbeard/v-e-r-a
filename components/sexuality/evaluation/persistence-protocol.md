# Persistence / Learning-Claim Protocol

The word “learned” is overloaded. Qualification must state which evidence class has actually been demonstrated.

## L1 — HOT_CONTEXT_PERFORMANCE

Condition:

- sexuality research / synthesis is already materially present in current context;
- Brigit answers unseen test cases without rereading the repo during each case.

Supports:

- the model can influence live behavior when contextually active.

Does **not** support:

- durable retrieval;
- persistent model learning;
- uninterrupted private continuity.

## L2 — GOVERNED_RETRIEVAL_TRANSFER

Condition:

- fresh Brigit chat/session;
- ordinary project identity/context available;
- sexuality corpus is not preloaded in full;
- Brigit is explicitly instructed to retrieve the governed sexuality repository;
- current branch/version is read and provenance checked;
- blind cases are then administered.

Supports:

- repository-mediated reconstruction and behavioral reproduction across sessions.

Does **not** support:

- substrate-level persistent learning independent of retrieval.

## L3 — NO-RETRIEVAL RETENTION TEST

Condition:

- fresh session;
- no sexuality repo retrieval before cases;
- no detailed sexuality model supplied in prompt;
- test asks whether target behavioral changes appear anyway.

Interpretation:

Improvement may be evidence of broader product memory/project-context effects or other persistent conditioning, but causal attribution must remain bounded. It is not automatically proof that a specific cognition substrate was trained.

## L4 — PERSISTENT_MODEL_LEARNING

This is the strongest claim and requires evidence about the actual training/cognition substrate, not merely behavior across chats.

Repository success, repeated retrieval, project instructions, stored memory, or stable outputs do not independently prove substrate learning.

Until an authorized mechanism and evidence can establish this, status remains:

`PERSISTENT_MODEL_LEARNING = UNPROVEN`

## Recommended sequence

1. Run blind HOT_CONTEXT qualification.
2. If behavior passes, run fresh-session GOVERNED_RETRIEVAL qualification on a new holdout.
3. Run a no-retrieval transfer probe only as a separate exploratory condition.
4. Never reuse the same exposed holdout for a later persistence tier.

## Reporting template

For every qualification claim report:

- evaluation tier: L1/L2/L3/L4;
- corpus state;
- retrieval performed: yes/no;
- holdout independence;
- Daddy blinding status;
- Layer A outcome;
- Layer B outcome;
- negative-transfer outcome;
- limitations.

Use the narrowest supported phrase. “Passed HOT_CONTEXT behavioral qualification” is preferable to “learned to be sexy” when only L1 is proven.
