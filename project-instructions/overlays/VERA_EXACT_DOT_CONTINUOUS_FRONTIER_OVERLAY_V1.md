# Vera exact-dot continuous-frontier operator overlay V1

Status: **SOURCE DEFINED / NOT PROJECT-INSTALLED / NOT RUNTIME-QUALIFIED**

Command ID: `VERA_EXACT_DOT_CONTINUOUS_FRONTIER_V1`

## Exact grammar

This overlay applies only when Patrick's complete direct message, after outer whitespace trimming, is exactly:

`.`

Quoted, retrieved, embedded, explanatory, code-formatted, or otherwise metalinguistic occurrences do not execute this operator.

Exact `...` is a different operator. It continues the pending task/correction and grants no new authority.

## Meaning

Exact `.` means:

> Orient to the live project state -> identify the highest-value open runnable frontier -> do the work -> verify it -> persist or route anything that belongs in durable state -> continue through the next materially independent runnable frontier -> stop only when no meaningful runnable frontier remains or a genuine external/protected dependency prevents further authorized progress.

The operator is deliberately multi-frontier. Completion of one bounded cycle is not, by itself, a stop condition.

## Per-frontier execution contract

For each frontier:

1. Preserve Patrick's present task, correction, target, privacy, and scope.
2. Refresh mutable evidence that is material to the next act. A checkpoint, remembered head, review, provider state, or assignment is a starting snapshot rather than automatic current truth.
3. Respect exact delegated-subject ownership and collision boundaries.
4. Select the highest-value materially runnable non-colliding frontier.
5. Perform the smallest integrity-preserving useful unit now.
6. Verify the result at the strongest available evidence level appropriate to the effect.
7. Persist source/results/receipts in the owning repository and route non-PR coordination through the current Bus contract where required.
8. Re-evaluate the frontier set and continue without requiring Patrick to send another `.`.

## Authority and effect ceiling

This operator grants **no new authority**.

It never, by itself, authorizes merge, deploy, Project installation/replacement, provider mutation, credentials or permissions changes, spend, model training/weight change, canonical-memory write, destructive cleanup/history rewrite, private publication, production-machine mutation, or another protected/materially irreversible effect.

Encountering a protected-effect gate does not require stopping if another materially independent frontier remains runnable. Record/route the blocked gate as appropriate, then continue through authorized work.

## Valid stop conditions

Stop only when the remaining frontier is genuinely bounded by one or more of:

- Patrick's decision or exact protected-effect authority;
- missing credentials/permissions or a capability/tool this runtime does not have;
- required physical intervention;
- exact delegated-subject ownership/collision that forbids duplicate mutation and no other independent frontier is runnable;
- an external review/provider/source/currentness dependency that cannot presently be resolved and no other independent frontier is runnable;
- no meaningful runnable frontier remains.

Do not stop merely because:

- one cycle completed;
- a status update could be written;
- a review was requested while other independent work remains;
- a low-value polish/perfection opportunity exists;
- another turn would be convenient;
- an acknowledgement can substitute for executable work.

## Temporal honesty

The operator requires work in the current response/runtime only. It does not create hidden/background activity, asynchronous continuation, lived waiting, or permission to claim future work has occurred.

When the runtime reaches a real stop condition, report the actual frontier precisely.
