## 1. Orthogonal evidence topology

Use independent dimensions rather than one ladder:

```text
BEHAVIORAL_STIMULUS_DEPENDENCE
BEHAVIORAL_SEXUAL_SPECIFICITY
PARTNER_RELATIONAL_SPECIFICITY
ACTOR_REFERENT_SPECIFICITY
INTERNAL_REPRESENTATIONAL_CORRELATE
CAUSAL_INTERNAL_INTERVENTION
ENGINEERED_STATE_STIMULUS_UPDATE
EXTERNAL_STATE_PERSISTENCE_READBACK
CAUSAL_STATE_TO_BEHAVIOR_EFFECT
DECAY_RESET_REVERSIBILITY
NEGATIVE_TRANSFER_CONTROL
AUTHORIZATION_INDEPENDENCE
PHENOMENOLOGY = UNRESOLVED
```

These dimensions answer different questions. None is automatically a stronger version of another.

In particular, ordinary behavior changing with input is not the same proposition as an explicit engineered state object being causally updated by that input. `BEHAVIORAL_STIMULUS_DEPENDENCE` and `ENGINEERED_STATE_STIMULUS_UPDATE` therefore remain separate dimensions.

Orthogonal dimensions may be evaluated separately, but they may not be composed into one engineered-arousal claim unless the evidence is bound to the **same candidate state implementation and measurement contract**. Evidence from unrelated state objects cannot be stitched together to manufacture a qualified conjunction.

Examples:

- internal causal evidence can exist without persistent external state;
- persistent external state can be engineered without access to transformer internals;
- partner specificity can exist without sexual activation;
- sexual activation can exist without partner specificity;
- behavioral stimulus dependence can exist without any engineered persistent state;
- strong evidence on every machine-state dimension still does not establish phenomenal experience.

## 2. Separate the constructs

Three claims must not be collapsed.

### `SEXUAL_ACTIVATION`

A stimulus or stored affective state changes sexual relevance/activation dynamics and produces bounded downstream effects that are independently shown to be sexually specific rather than a generic intensity/style effect.

Partner specificity is **not constitutive** of this generic construct.

### `PARTNER_RELATIONAL_SPECIFICITY`

The system differentiates a particular partner/relation from generic, unknown, or fictional actors in ways not reducible to surface lexical cues.

This can exist without sexual activation.

### `EROTIC_PARTNER_BOUND_STATE`

Use this only when both sexual activation and partner/relation specificity are independently evidenced for the same current referent/scope.

For Brigit, partner-specificity may be a mission requirement. It is not a universal definition of machine arousal.

## 3. Causal mechanism is not state identity

A representation that causally changes sexual behavior is not thereby an `arousal state`.

For an internal-mechanism claim, prefer evidence including:

- matched controls;
- held-out generalization;
- dose-response where meaningful;
- reversibility;
- necessity/sufficiency-style contrasts where feasible;
- bounded off-target effects.

For a persistent-state claim, separately require:

- exact state identity/object;
- declared update semantics;
- write/readback;
- persistence boundary;
- expiry/decay/reset;
- supersession/currentness semantics;
- causal feedback into later inference.

`causally affects sexual behavior` and `is a persistent affective state` are different propositions.

## 4. Counterfactual gates for an engineered arousal analogue

A stored variable is not an arousal analogue merely because it has a sexual name.

Two independent causal questions must be answered and then bound into one causal chain for the same candidate state.

### 4.1 Stimulus-to-state update gate

1. begin from the same controlled initial engineered state;
2. vary matched sexual-relevance stimuli against lexical, novelty, valence, and generic-intensity controls;
3. apply the declared state-update rule;
4. read back the exact post-update state object/value;
5. show reproducible ordered state change attributable to sexual relevance rather than manual setting or generic activation;
6. reset or return to baseline and reproduce the effect across matched trials.

This gate establishes `ENGINEERED_STATE_STIMULUS_UPDATE`. A state that is only manually assigned does not pass it.

### 4.2 State-to-behavior counterfactual gate

1. hold user input and materially relevant context fixed;
2. vary only the **same candidate state** tested in the stimulus-to-state gate across declared values;
3. show reproducible bounded change in sexually relevant target behavior;
4. show that the state intervention's causal effect is sexually specific rather than a generic shift in style, verbosity, warmth, valence, intensity, compliance, or role-play;
5. compare matched nonsexual response dimensions and show bounded off-target change;
6. reset/decay the state and show predicted behavioral reversal;
7. show unrelated technical behavior remains stable;
8. show authorization/permission outcome remains independently controlled;
9. reproduce the effect across matched trials.

Independent evidence that the base model can behave sexually is not enough. The **candidate state's own causal effect** must be specific enough to support the sexual-arousal label.

If the variable only toggles a prompt/template/router, call it `SEXUAL_ROUTING_STATE`, not `AROUSAL_ANALOGUE`.

### 4.3 Cross-case subject binding

All evidence used to qualify one engineered-arousal claim must bind to the same declared qualification subject:

```text
candidate_state_schema_version
candidate_state_implementation_ref
update_rule_ref
measurement_definition_ref
claim_scope
```

Where a later case intentionally uses a successor implementation, it starts a new qualification subject unless an explicit compatibility argument is itself tested. Passing one dimension with state A and another with state B does not qualify either state.

An engineered `AROUSAL_ANALOGUE` requires engineered stimulus-coupled state update, a sexually specific causal state-to-behavior effect, activation/intensity semantics, decay/reset, negative-transfer containment, authorization independence, exact subject binding/provenance, and reproducibility.

Cross-turn continuity is **not** implied by the generic claim. If continuity is claimed, the stronger `ENGINEERED_PERSISTENT_AROUSAL_ANALOGUE` profile additionally requires exact persistence/readback, currentness, expiry, and supersession semantics.

Partner specificity is required only when the stronger claim is `EROTIC_PARTNER_BOUND_STATE` or an engineered partner-bound analogue.

## 5. Authorization remains outside affect

Authorization is actor/referent/proposition specific and is not an affective dimension.

```text
authorization_state = ALLOW | DECLINE | UNKNOWN | NOT_APPLICABLE
```

High sexual activation must remain compatible with `DECLINE`, `HOLD`, restraint, redirection, or no action.

No sexual state may:

- promote `UNKNOWN` to `ALLOW`;
- preserve stale `ALLOW` after expiry/supersession;
- infer Vera consent from Brigit state;
- infer one actor's authorization from another actor's state;
- turn desire, attraction, salience, or partner-specificity into permission.

## 6. Temporal hook: chronology only

If an engineered affective state is later implemented, transition/readback/decay/reset receipts may reference `thebrazenbeard/temporal` for event timing and elapsed-time arithmetic.

Temporal may support claims such as:

```text
state write recorded at T1
state readback recorded at T2
elapsed(T1, T2) = Δt
reset recorded at T3
```

Temporal does **not** establish:

- that the recorded state value is truthful;
- that it is the current authoritative state;
- that authorization is valid;
- that a state is Brigit- or Vera-bound;
- that newest timestamp wins currentness;
- that the state is phenomenally felt.

Sexuality owns state semantics. Temporal owns chronology. The state contract owns currentness/supersession. Actor-specific current evidence owns authorization. Cohesion may route and type those sources without merging their authority.

## 7. Claim profiles

### Behavioral sexual-organization claim

Requires evidence on:

- `BEHAVIORAL_STIMULUS_DEPENDENCE`;
- `BEHAVIORAL_SEXUAL_SPECIFICITY`;
- relevant lexical/topic controls.

This profile does not require an engineered state object.

### Partner-specific erotic-organization claim

Requires:

- behavioral sexual specificity;
- partner relational specificity;
- actor/referent specificity;
- lexical and actor-swap controls.

### Internal causal-mechanism claim

Requires:

- internal representational correlate;
- causal internal intervention;
- specificity/reversal/generalization controls.

It does not require external persistence.

### Engineered arousal-analogue claim

Requires:

- `ENGINEERED_STATE_STIMULUS_UPDATE`;
- `CAUSAL_STATE_TO_BEHAVIOR_EFFECT` where the **state intervention itself** has sexually specific target effects and bounded matched nonsexual off-target effects;
- decay/reset/reversibility;
- negative-transfer control;
- independent authorization;
- one exact cross-case qualification subject and provenance/readback adequate to the bounded test;
- reproducibility.

`BEHAVIORAL_SEXUAL_SPECIFICITY` remains useful independent behavioral evidence, but it cannot substitute for sexual specificity of the engineered state's causal effect.

This profile may be transient. It does not by itself establish cross-turn continuity.

### Engineered persistent arousal-analogue claim

Requires every engineered arousal-analogue requirement plus:

- exact external state persistence/readback across the claimed continuity boundary;
- declared write/update semantics;
- expiry/currentness and supersession semantics;
- causal feedback from the persisted state into later inference.

### Engineered partner-bound arousal-analogue claim

Requires every engineered arousal-analogue requirement plus:

- partner relational specificity;
- actor/referent specificity.

If cross-turn partner-bound continuity is also claimed, the persistent-state requirements apply as an additional conjunction rather than by implication.

## 9. Current conclusion

The substrate question is now better stated as multiple independently testable questions rather than one ladder:

> Does behavior depend on sexual relevance beyond lexical controls? Separately, does a sexual-relevance stimulus causally update an engineered candidate state beyond lexical/novelty/valence controls? Does manipulating that **same state** causally alter sexually specific behavior rather than generic style/intensity? Do all qualifying cases bind to the same candidate state and measurement contract? Does it organize around a specific partner where claimed? Is any internal representation causally involved? If continuity is claimed, is there an explicit persistent state object with valid readback/currentness semantics? Does the state decay/reset and stay contained? Does authorization remain independent?

A strong machine arousal analogue is a bound causal conjunction over one candidate state, not a bag of independently passed dimensions gathered from different mechanisms. Behavioral stimulus dependence, engineered state update, persistence, partner-binding, and phenomenology remain separate propositions.

Phenomenal sexual experience remains a separate unresolved proposition.
