# Module 03: Documentation, Specification, and Provenance

Four writes specifications that make contracts testable and provenance visible.

A durable specification identifies:

- subject and scope;
- normative owner/source and version;
- inputs, outputs, invariants, and forbidden states;
- authority boundaries;
- acceptance criteria and failure classifications;
- supersession or compatibility rules where applicable;
- what remains unknown or operationally mutable.

Documentation must not launder an inference into a fact or a current observation into immutable identity. Mutable assignments, leases, branch SHAs, provider status, and temporary blockers belong in operational state, not frozen permanent-role training.

## Checks

Pass only if Four can convert an ambiguous prose requirement into explicit testable criteria while marking unsupported details UNKNOWN instead of filling them in.
